# 로그 시스템 4차 계약

작성일: 2026-10-31. 범위: 실제 사격·발사체 명중·무기별 전투 요약·받은 실제 피해와 출처·활성 장착 시간. 1~3차의 세션/고정 시계/저장·종료 계약을 사용한다. 탄약 경제 집계는 추가하지 않았다. Unity 실행 검증은 사용자 확인 대기다.

## 연결과 소유자

GameManager.Logging의 기존 초기화에서 순수 `LogCombatCollector`를 생성하고 `Telemetry.RegisterCollector`에 combat 키로 등록한다. PlayerWeapon.CombatLog와 PlayerHealth.CombatLog에 같은 관측자를 연결한다. OnDestroy는 기존 종료 처리 뒤 자신이 연결한 관측자만 해제한다. 진행 중인 발사체는 생성 당시 LogShotContext를 유지하며 새 GameManager나 전역 세션을 조회하지 않는다.

기존 Fired/HandFired/EnemyImpact를 추가 구독하지 않는다. HUD·사운드·입력의 기존 호출 순서와 의미를 유지했다. 기존 두 ApplyDamage 시그니처도 유지하고 출처를 받는 세 번째 인자를 가진 오버로드를 추가했다. 씬·프리팹·입력·AI·보상·탄약 소비·사격 조건·낮은 벽 판정은 변경하지 않았다.

## 실제 성공 사격과 생성 결과

TryFire의 기존 재장전/카메라/PickHand 실패 반환 뒤, 발사할 WeaponInstance와 handSettings를 확보한다. 기존 TakeShot → Fired → HandFired → 사운드/총구 이펙트 → 실제 origin 결정 순서를 유지한다. 카메라 위치 폴백까지 결정된 origin과 발사 당시 개체/손을 사용해 LogShotContext를 만든다. 이후 기존 발사체 생성 루프의 반환값을 관측하고 루프 끝에서 player_shot을 한 번 기록한다.

실제 성공 사격은 게임이 TakeShot을 수행한 사격 동작이다. 프리팹 누락 등으로 발사체 생성이 모두 실패해도 이 사격 사실과 기존 탄약 소비는 되돌리지 않는다. requestedProjectileCount는 설정된 발사체 수, createdProjectileCount는 실제 non-null 반환 개수, failedProjectileCount는 null 반환 개수다. 생성 실패를 성공한 발사체나 단순 사격 실패로 바꾸지 않는다.

단발도 매번 별도 shotId를 발급한다. 기존 pelletGroup은 단발 0·산탄 전투 그룹이라는 기존 의미를 그대로 유지하며 로그 ID로 사용하지 않는다. 각 발사체 시도는 별도 projectileId를 갖고, player_shot.projectileIds에는 실제 생성된 ID만 들어간다. 무기 참조의 세션 내 안정 ID는 기존 GetWeaponId다. 손 0은 right, 손 1은 left다.

player_shot payload:

| 필드 | 의미 |
|---|---|
| shotId, weaponInstanceId, weaponTypeId, hand | 사격 당시 식별자. 무기 종류를 확인하지 못하면 unknown, 개체 미연결은 null |
| origin | 실제 발사 origin의 월드 x/y/z |
| originWaveNumber, originPhase | 사격 발생 당시 웨이브/단계 |
| firedElapsedSeconds | 사격 스냅샷 생성 당시 공통 고정 시계 |
| requestedProjectileCount, createdProjectileCount, failedProjectileCount | 명목 발사체 수와 실제 생성 결과 구분 |
| projectileIds | 실제 생성된 발사체 ID 배열 |

쿨다운·빈 탄창·입력 차단 등으로 실제 사격 경로에 들어가지 않은 입력은 player_shot이 아니다. UI용 Fired/HandFired가 같은 발사에서 호출돼도 로그를 두 번 만들지 않는다. 탄약 절감은 기존 게임 코드가 처리하며 이 단계는 그 경제 집계를 추가하지 않는다.

## 명중과 처치

Projectile.Shot에 logContext/projectileId/attackSource를 추가했다. Projectile.Impact에도 사격 문맥과 발사체 ID·대상 ID/종류·실제 적 체력 감소량을 추가했다. 발사체마다 값으로 전달한 출처를 유지하므로 비행 중 플레이어가 다른 무기를 들어도 결과는 발사 당시 무기로 귀속된다.

적에게 실제로 충돌한 경우에는 기존 Enemy.TakeHit 전후 체력을 비교해 실제 감소량을 계산한다. 적 체력의 음수 초과 피해는 실제 감소량에 포함하지 않는다. 기존 CombatHitResult.damageDealt는 기존 피드백 의미를 유지하고 바꾸지 않았다. 적 접촉 사실과 실제 피해량은 별도다. 피해가 0인 적 접촉도 명중이고 실제 피해량은 0이다. 이미 죽은 적을 건너뛰는 기존 판정도 유지한다.

projectile_impact payload는 shotId/weaponInstanceId/weaponTypeId/hand/originWaveNumber/originPhase, impact, lateResult다. impact는 projectileId/hitEnemy/killed/targetId/enemyTypeId/actualDamage/point다. 봉투의 waveNumber/phase/elapsedSeconds는 충돌이 실제 관측된 단계다. 지형 충돌도 hitEnemy=false로 남길 수 있으며 수명/사거리 종료와 강제 취소는 명중으로 만들지 않는다.

전투 요약은 발사 당시 웨이브·무기 개체별로 누적한다. 발사체 ID별 명중은 한 번, shotId별 적 하나 이상 명중은 한 번이다. 산탄 여러 발이 같은 적 또는 여러 적에 맞아도 hitShots는 1이고 hitProjectiles는 실제 맞은 발사체 수다. 처치는 Impact의 killed 경로 하나만 무기별 집계에 사용하며 대상 ID별 중복을 막는다. 대상 ID는 현재 Unity Enemy의 GetInstanceID를 문자열로 복사한 웨이브 내 식별자이며 세션/게임 간 영구 ID가 아니다.

기존 WaveController.EnemyKilled → GameManager 보상/전체 처치 수는 유지한다. 그 이벤트를 무기별 처치에 다시 더하지 않는다. IDamageable 직접 호출처럼 발사 출처 없는 적 처치는 무기 처치로 추정하지 않는다. Stop/CancelAll의 강제 제거는 무기 명중·처치로 집계하지 않는다.

## 받은 피해와 마지막 치명 피해

`LogAttackSource`는 적 종류·적 무기 ID·공격 위치를 불변 값으로 복사한다. 근접 공격은 해당 공격의 위치와 종류를 전달하고 무기는 unarmed다. 원거리 공격은 발사 때의 실제 origin과 종류/무기를 Projectile.Shot.attackSource에 보관한다. 적이 죽거나 owner Transform이 사라진 뒤에도 이 값은 유지된다. 알 수 없는 종류/무기는 unknown이다.

PlayerHealth는 기존 방어력 적용/체력 상한 처리를 수행한 뒤 실제 `previous - CurrentHealth` 감소량을 관측한다. 순서는 다음과 같다.

`기존 피해 계산 → LogCombatCollector.PlayerDamaged → 기존 HealthChanged → 기존 DamagedFrom → 기존 Died/OnPlayerDied`

PlayerDamaged는 먼저 lastDamage를 값 복사하고 받은 피해 집계와 player_damage 레코드를 생성한다. 따라서 치명 피해가 2차 death_snapshot과 중단 combat 요약에 포함된다. 방어력으로 실제 체력이 줄지 않은 경우는 피격 수/받은 피해량에 추가하지 않는다. 과잉 피해는 남아 있던 실제 체력까지만 기록한다. 이는 명목 피해·발사체 수와 별개다.

기존 `ApplyDamage(amount)`는 출처 unknown/공격 위치 null이다. 기존 `ApplyDamage(amount, position)`은 종류/무기는 unknown이며 전달받은 위치는 보존한다. 새 `ApplyDamage(amount, position, source)`는 출처를 함께 전달하고 기존 방향 피드백의 position 의미를 유지한다.

player_damage payload와 death_snapshot.lastDamage는 기존 LogDamageSnapshot의 enemyTypeId/enemyWeaponId/attackPosition/actualDamage다. 받은 피해 요약은 발생 당시 열린 웨이브에서 적 종류별 실제 감소량과 피격 수를 누적한다. 적 원거리 출처를 현재 살아 있는 적이나 현재 장착 무기에서 역추정하지 않는다.

## 활성 장착 시간과 요약

초기 실제 장착 상태와 기존 GameManager.ApplyActiveWeapon의 최종 적용 뒤에만 손에 든 개체들을 관측한다. 아킴보 Configure 내부의 임시 단일 손 상태를 별도 전환으로 세지 않는다. 같은 개체/종류/손/슬롯 배열이면 재호출을 무시한다. UI Refresh나 파츠 스탯 갱신만으로 장착 전환을 생성하지 않는다.

전환 시 이전 활성 구간을 공통 ElapsedSeconds로 마감하고, 웨이브 종료/사망/나가기 중단 시 현재 구간도 마감한다. 웨이브가 열리지 않은 상점 시간과 미사용 휴대 슬롯은 제외한다. 양손은 각 개체에 시간을 각각 더하므로 같은 종류의 양손 합계가 웨이브 시간보다 클 수 있다. 이는 발사 중인 시간이나 조작 허용 시간만을 측정하는 값이 아니라, 해당 웨이브에서 그 손에 장착되어 있던 시간이다. 고정 틱이 멈추면 이 시간도 멈춘다.

실제 전환은 weapon_equipped payload의 weapons 배열(LogHeldWeaponSnapshot)로 기록한다. combat 요약은 summaries.combat.collectionStatus=collected이며 data는 다음 배열이다.

| 배열 | 내용 |
|---|---|
| weapons | instanceId/weaponTypeId별 equippedSeconds, shots, requestedProjectiles, projectiles, hitProjectiles, hitShots, kills, actualDamageDealt |
| weaponTypes | 위 개체 수치의 종류별 합계. instanceId=null |
| damageReceived | enemyTypeId별 actualDamage/hits |

projectiles는 실제 생성 수다. shots는 사격 묶음 수, hitShots는 적 하나 이상 명중한 묶음 수다. 장착 시간이 0이어도 실제 사격 출처가 확인되면 그 개체의 사격 통계를 보존한다. 통계가 전혀 없는 종류의 가짜 0 행은 만들지 않는다. combat은 이제 실제 등록 수집기이고 ammo는 여전히 not_collected/null이다.

## 늦은 결과와 종료

마감 시 LogGameLifecycle은 원본 wave_summary를 직렬화한 뒤 선택적 `ILogWaveSummaryReceiver.SummaryClosed`에 값 계약을 전달한다. combat 수집기는 아직 종료되지 않은 발사체가 있는 웨이브만 보정용 원본 전체 요약을 보관한다. 원본의 다른 수집기·자원·보상·시각 값도 함께 유지한다.

웨이브가 닫힌 뒤 적 명중이 발생하면 원래 발사 웨이브/무기 개체의 집계를 갱신하고 같은 summaryId와 증가하는 revision의 `wave_summary_correction`을 추가한다. payload는 combat만 바뀐 완전한 대체 요약이다. 원본 줄을 덮어쓰지 않는다. 분석기는 키별 가장 큰 revision 하나만 합계에 적용한다. 봉투는 결과 발생 단계/웨이브를 사용하므로 payload.plan.waveNumber와 다를 수 있다.

기존 lifecycle의 kills는 처치가 실제 발생한 웨이브 기준이고, combat의 무기 결과는 발사 웨이브 기준이다. 경계를 넘는 탄에서 둘을 같은 범위의 합계로 단정하지 않는다. 해당 차이는 raw projectile_impact의 발생 봉투와 originWaveNumber/originPhase로 해석한다. 다음 웨이브의 무기나 집계로 옛 사격 결과를 옮기지 않는다.

현재 실제 게임의 WaveController.Stop은 기존대로 진행 중 발사체를 취소한다. 이 경로를 바꾸어 늦은 충돌을 일부러 만들지 않았다. 보정 경로는 순수 입력 검사로 경계 뒤 결과를 주입해 검증했다. 수명/사거리/충돌/CancelAll은 생성된 발사체의 종료를 알리고, 마지막 발사체가 종료되면 보정용 요약을 해제한다. 세션이 이미 끝났거나 저장이 중단되어도 발사체의 상태 정리는 수행하며 새 로그를 생성하지 않는다.

세션 종료 뒤 Impact/새 사격/피해 관측은 옛 서비스에서 거부된다. 새 세션으로 라우팅하지 않는다. 관측자의 예외와 저장 실패는 기존 제한 경고/진단으로 격리하며 게임 보상/소비를 취소하지 않는다. 비활성 설정에서는 사격 문맥을 만들지 않는다.

## 검사와 사용자 Unity 확인

`.omo/verification/log-phase4/RESULTS.md`에 명령과 결과를 기록했다. 순수 집계 입력은 실제 충돌/입력을 실행하지 않는다. 아래 사용자 확인은 아직 수행하지 않았다.

1. 새 C# 소스와 meta를 import하고 컴파일을 확인한다. Game 진입 후 정상/중단 wave_summary의 combat이 collected이고 ammo는 not_collected인지 확인한다.
2. 단발·산탄·아킴보로 사격한다. 성공 사격당 player_shot 하나, 단발에도 서로 다른 shotId, 실제 오른손/왼손과 origin을 확인한다. 기존 카메라 위치 폴백 조건에서도 기록한 origin을 실제 Projectile.Launch 값과 비교한다. 낮은 벽 판정은 이번에 개선하지 않았다.
3. 산탄을 한 적/여러 적에 맞히고 빗나가게 한다. shots/hitShots와 projectiles/hitProjectiles를 구분하고 처치가 중복되지 않는지 확인한다. HUD·소리·탄약 소비·저지력/넉백 의미가 기존과 같은지 확인한다.
4. 탄 비행 중 무기를 바꾼다. 명중/처치는 발사 당시 개체/손에 귀속되어야 한다. 플레이어 발사체 생성 실패 환경을 별도로 시험한다면 사격 사실·명목 발사체 수·실제 생성 수를 구분하고 원래 소비/실패 정책이 유지되는지 확인한다.
5. 근접·원거리 적에게 피해를 받고 방어력/남은 체력을 반영한 실제 감소량을 비교한다. 적이 발사 후 먼저 죽은 경우에도 출처/공격 위치가 보존되어야 한다. 마지막 치명 피해의 player_damage가 death_snapshot/중단 요약보다 앞서는지 확인한다.
6. 슬롯/아킴보 전환과 같은 상태의 반복 Refresh를 비교한다. 실제 활성 개체의 장착 시간만 누적되고 미사용 휴대 슬롯·상점 시간이 포함되지 않아야 한다. 사망/나가기에서도 구간이 마감되어야 한다.
7. 기존 웨이브 종료/게임 오버의 발사체 취소와 Title 재시작에서 새 세션 오염이 없는지 확인한다. 보정 경로는 현재 Stop 정책상 일반 플레이에서 발생하지 않을 수 있으며 실제 취소 정책을 바꾸어 확인할 필요는 없다.

`Docs/로그-시스템-4차.synthetic.jsonl`은 메모리 저장소와 실제 순수 수집기로 만든 합성 예시다. synthetic-* 맵/무기/적과 주입한 UTC/피해 입력을 사용하며 실제 Unity 플레이 로그가 아니다. 실제 충돌·이벤트 순서·화면·파일 위치·프레임 영향은 사용자 검증 대기다.
