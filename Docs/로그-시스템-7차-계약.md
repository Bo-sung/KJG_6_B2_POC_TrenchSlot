# 로그 시스템 7차: 실제 상점 제시·구매 시도

구현일: 2026-10-31. Unity 실행·Play Mode·Unity 빌드·Unity API 실행 검증은 하지 않았다.

## 현행 범위와 소유자

GameManager가 세션별 LogShopCollector를 소유한다.
구매 관측 경계는 TryBuyWeapon/Part/Stat/Ammo/SlotUpgrade 전체다.
기존 private Buy*의 판정·가격·문구·보상 순서를 유지하고 공통 RunLoggedPurchase로 정상 반환·모든 조기 실패·예외를 감싼다.
실제 구매가 예외를 던지면 그대로 전파하며 로깅 때문에 구매를 취소하거나 환불하지 않는다.

현재 ShopData/ShopPresenter/GameManager에는 유료 회복 상품과 TryBuyHeal이 없다.
회복은 슬롯 회전 정책이므로 과거 회복 판매 API/가격/상품을 복원하지 않았다.
최대 체력 스탯 구매의 실제 체력 변화는 구매 스냅샷과 actualHealthRestored에 남는다.
유료 회복 구매·최대 체력에서의 회복 구매 실패 검사는 현행 정책에 해당하지 않는다.

## 실제 제시 단위

ShopPresenter.Logging이 LateUpdate에서 현재 UI 값을 관측한다. UI 클릭 시에도 최신 노출을 확보한 뒤 명시적 참조를 전달한다.
ShopView/ShopRowView는 기존 표시·버튼·레이아웃을 바꾸지 않고 읽기 API만 제공한다.

- 실제 활성 행 중 투명도 0·0 크기·Canvas 비활성·스크롤 viewport/Mask/RectMask2D/루트 Canvas 밖의 행은 제외한다.
- 일부 면적이 보이는 행은 포함한다. 테두리가 닿을 뿐 교차 면적이 없는 행은 제외한다.
- 단위는 weapon_catalog/weapon_detail/weapon_buy, 선택 무기의 part_catalog/part_detail/part_buy, stat/ammo/upgrade다.
- 선택하지 않은 무기의 파츠·프리팹 행 수를 넘는 상품·숨긴 잠금 탄약은 제시하지 않는다.
- 잠긴 무기/파츠가 실제 표시된 경우 locked로 남긴다. 선택 가능한 목록 행과 구매 가능 여부를 구분한다.
- 품절·구매 완료 카드는 실제 보이면 sold_out/already_purchased로 남긴다. 품절 빈 칸은 productId=null인 자리 표시이며 상품으로 세면 안 된다.
- 무료 장착/분리·휴대 슬롯 카드·아킴보 버튼은 유료 상품 제시 목록에서 제외한다.

이는 기하학적 UI 표시 범위이며 사용자가 실제로 읽었는지·다른 창이 덮었는지·시선이 머물렀는지를 뜻하지 않는다.
현재 상점의 스크롤·마스크·화면 Canvas 구조에 맞춘다. 실제 노출과 키보드/패드 자동 스크롤은 사용자 Unity 확인 사항이다.
UI 레이아웃/가시성 읽기는 메인 스레드에서 수행하며 Canvas 강제 재배치나 씬/프리팹 변경은 없다.

## 제시 이벤트와 ID

shop_offers_presented:
offerSetId, revision, presentation.
presentation에는 balance, selectedWeaponId/selectedPartId, 실제 보이는 offers 배열이 있다.

상품 ID는 `itemType:Uri.EscapeDataString(itemId)`이다.
같은 종류의 상품을 반복 구매해도 ID는 같다. 실제 생성된 개체 ID는 별도로 구분한다.
표시 위치 placement와 row가 목록/상세/대상 슬롯의 서로 다른 노출을 구분한다.

각 offer는 product, placement/row, state, purchasable, failureCode, 실제 label/priceText/선택 상태를 가진다.
product는 종류/테이블 ID/productId/현재 가격/요청·실제 대상 슬롯/대상 무기 개체/업그레이드 칸/데이터 유효성이다.
price는 기존 ShopInfo의 현재 구매 견적이다. priceText는 실제 화면 문자열로 최대·빈 가격 등과 구분한다.
알 수 없는 상품 가격은 null, 계산 가능한 무료 가격은 실제 0이다.

구매 가능 여부는 현재 UI가 사용하는 해금·잔액·예비탄·품절·구매 제한/버튼 상태다.
무기 교체의 물리적 바닥 자리 등 실제 API에서만 확정하는 조건까지 성공을 보장하는 값은 아니다.
그 사유는 실제 시도 실패(no_drop_space 등)로 기록한다.
displayReason/label은 실제 화면 텍스트이며 구매하지 않은 이유를 추정하지 않는다.

상점 열기마다 별도 OfferSet ID 공간에서 새 ID를 만든다. 첫 revision=0이다.
동일한 실제 제시/선택/가격/잔액/상태는 반복 Refresh에서도 추가 기록하지 않는다.
가격·잔액·선택·스크롤 노출·상세 문구·진열 상태가 달라지면 같은 offerSetId의 revision을 증가시킨다.
닫힌 내부 Refresh는 기록하지 않고, 닫았다 다시 열면 새 offerSetId/revision=0이다.
기록 크기 제한/실패로 제시가 기록되지 않았다면 그 제시 참조를 발급하지 않는다.

## 구매 시도와 결과

shop_purchase_attempt:
attemptId, product, offer(또는 null), before.

attemptId는 기존 PurchaseAttempt ID 공간을 쓴다.
API의 선택적 _logOffer 기본값은 null이다. 화면이 열려 있어도 직접 API 호출을 자동으로 특정 노출에 연결하지 않는다.
UI만 최신 화면에 실제로 보인 구매 행의 offerSetId/revision/productId/placement/row를 명시적으로 전달한다.
다른 상품·잘못된 슬롯·낡은 revision·이미 닫힌 제시의 참조는 null로 떨어진다.

shop_purchase_result:
동일 attemptId/product/offer, success, failureCode, 기존 displayReason,
before/after, actualSpent, actualHealthRestored, createdWeaponIds, createdPartIds, ammoChanges.

- before/after에는 잔액·체력·위치·휴대 무기/개체/탄약, 모든 파츠 개체/장착 위치, 스탯 횟수와 실제 적용 배율/최대 체력/예비탄 한도, 퍽 스택/진열 칸 상태가 있다.
- 무기 ID는 기존 세션별 안정 ID, 파츠 ID는 sessionId:part:기존 Uid다. 반복 파츠 구매도 새 개체만 createdPartIds에 남는다.
- 실제 대상 슬롯은 product.resolvedTargetSlot로 요청 슬롯과 구분한다. 빈 슬롯 자동 선택 정책도 유지한다.
- actualSpent는 관측 구간의 전후 순 잔액 감소량이다. 견적 price와 구분하며 실패 시 확인된 0은 0이다.
- actualHealthRestored는 확인된 실제 체력 증가량이다. 상태를 모르면 actualSpent/actualHealthRestored와 생성 개체 목록은 null이다.
- 외부 재진입 코드가 같은 구간에 별도 거래를 수행하면 전후 순 변화에 그 영향이 포함될 수 있다.

구매 완료는 문맥당 한 번만 기록한다. 다른 세션의 문맥은 거부한다.
끝나기 전에 API가 세션을 종료시키거나 결과 직렬화에 실패하면 가능한 경우 shop_purchase_incomplete를 session_end 전에 남긴다.
구매 예외는 result.success=false/failureCode=exception으로 구분하고 원래 예외 동작을 보존한다.
설정 비활성/저장 실패는 게임 구매와 보상을 막지 않는다. 공통 버퍼·진단·경고 정책을 유지한다.

## 실패 코드

기존 사용자 표시 문자열은 바꾸지 않는다. 알려진 문구와 상품/진열 문맥을 순수 분류기로 해석한다.

| 코드 | 의미 |
|---|---|
| shop_closed | 정비 시간 밖 실제 API 호출 |
| insufficient_funds | 실제 잔액 부족 |
| invalid_product | 무효/없는 상품 또는 데이터 |
| locked | 유효 상품의 시대 해금 전 |
| invalid_target_slot | 가득 찬 휴대 슬롯의 잘못된 교체 요청 |
| invalid_offer_index | 범위 밖 슬롯 업그레이드 칸 |
| sold_out / already_purchased / purchase_limit | 빈 진열 / 구매 완료 / 스택 제한 |
| maximum_reserve / no_effect | 최대 예비탄 / 실제 보충이 없어 기존 환불 처리 |
| missing_pickup_prefab / no_drop_space | 기존 무기 교체 실패 조건 |
| purchase_in_progress | 기존 탄약 구매 재진입 거부 |
| exception / unknown | 예외 / 아직 분류하지 않은 원문 |

성공 failureCode는 null이다. 유효하지 않은 탄약 ID의 기존 표시가 잠김 문구라도 데이터 유효성을 확인해 invalid_product로 구분한다.
범위 밖 업그레이드의 기존 품절 문구도 그대로 두고 코드만 invalid_offer_index로 구분한다.

## 4~6차와 중복 방지

팩 구매·신규 무기 장전탄·파츠 탄창 반환/폐기·최대량 강화에 causeId=attemptId를 전달한다.
실제 탄약 변경/경제 집계는 기존 LogAmmoCollector 한 곳이 소유한다.
ammoChanges는 해당 원본 transactionId와 실제량을 복사한 참조이며 다시 지급/집계하지 않는다.
팩은 명목 수량이 아닌 현재 상한에 실제로 추가된 예비탄을 기록한다.

슬롯 보상·지갑/인벤토리 이벤트·무료 장착/분리·슬롯 선택·아킴보 전환은 구매 시도를 만들지 않는다.
무료 조작의 무기/탄약 변동은 기존 4~5차 경로를 유지한다.
구형 ShopPurchase 단일 이벤트 API/DTO를 제거해 두 구매 방식이 함께 기록되지 않게 했다.

## 검증과 사용자 확인

`.omo/verification/log-phase7/`는 실제 AmmoInventory/PlayerWallet과 현재 JSON, 제어한 관측 입력을 사용한다.
GameManager/ShopPresenter/ShopInfo의 Unity 실행 대신 전체 C# 컴파일과 경계·참조 정적 검사를 수행했다.
제어 입력 검사를 실제 게임 구매 성공으로 주장하지 않는다.
`Docs/로그-시스템-7차.synthetic.jsonl`은 합성 예시다.

사용자 Unity 확인:

1. 상점 열기/닫기와 동일 Refresh, 잔액·가격·선택·상세 변경에서 offerSetId/revision을 비교한다.
2. 무기/파츠/보급 목록 스크롤, 잠김 표시·숨김·품절·구매 완료 카드, 행 수 부족 상태에서 실제 노출만 기록되는지 확인한다.
3. 무기·추가 파츠·스탯·팩·슬롯 업그레이드 구매 성공/실패와 기존 가격·문구·보상·장착 정책이 동일한지 확인한다.
4. 돈 부족·잘못된 ID/교체 슬롯/업그레이드 칸·잠김·최대 예비탄·구매 완료·품절·상점 밖 API 호출의 코드/원문/잔액을 비교한다.
5. 팩의 부분 보충, 신규 무기 장전탄, 파츠 반환/폐기, 최대 예비탄 강화에서 실제량과 ammo_changed transactionId/causeId가 일치하는지 확인한다.
6. 무료 장착/분리·휴대 슬롯 선택·아킴보·슬롯 보상에서 구매 이벤트가 생기지 않는지 확인한다.
7. 실제 키보드/패드 포커스·자동 스크롤·HUD를 확인하고, 종료 후 Tools > POC > Verify Unified Telemetry File로 제시 revision/구매 1:1/탄약 원본 참조를 검사한다. 이 메뉴는 AI가 실행하지 않았다.
