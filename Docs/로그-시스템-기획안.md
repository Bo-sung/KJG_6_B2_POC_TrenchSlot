# 로그 시스템 기획안

## 구현될 로그 요약

아래 표의 로그 항목은 실제로 남기는 레코드와 값을 뜻한다. 이동 경로·난이도·구매 성향 등은 기록된 값을 분석해 얻는 결과이며 로그 이름으로 대신하지 않는다. 모든 레코드에는 아래 공통 필드를 함께 넣는다.

| 수집 방식 | 기록할 로그 | 수집 시점 |
|---|---|---|
| Fixed Delta Time | 현재 시각·플레이어 위치(x, z)·카메라 방향·장착 무기·게임 단계 | 조작 가능한 각 FixedUpdate에서 1회 기록 |
| Fixed Delta Time | 현재 시각·웨이브 번호·적 종류별 생존 수 | 조작 가능한 각 FixedUpdate에서 플레이어 위치와 같은 틱에 기록 |
| 이벤트 | 세션 시작 UTC·빌드/데이터 버전·맵 ID·적용 fixedDeltaTime | 한 판이 시작될 때 |
| 이벤트 | 세션 종료 UTC·플레이 시간·종료 사유·최종 도달/마지막 완료 웨이브·총 처치 수 | 한 판이 종료될 때 |
| 이벤트 | 웨이브 시작 시각·제한 시간·예정 적 종류/수·체력·소지금·무기/탄약 | 웨이브가 시작될 때 |
| 이벤트 | 웨이브 종료 시각/사유·처치 수·체력·소지금·무기/탄약·실제 보상/회복량·전멸 시각 | 웨이브가 완료되거나 중단될 때 |
| 이벤트 | 회전 ID·시작 시각·실제 비용·회전 전 소지금·체력·생존 적 수·플레이어 위치 | 슬롯 회전이 시작될 때 |
| 이벤트 | 회전 ID·결과 시각·결과 심볼/당첨 항목·실제 지급 돈/탄약·지급 후 소지금 | 슬롯 결과가 확정될 때 |
| 이벤트 → 요약 | 탄종별 시작/종료 탄약량·발사 소모량·출처별 실제 획득량·재장전 부족/빈 탄창 발사 시도 횟수 | 발생 시 누적하고 웨이브 완료·중단 시 합계 기록 |
| 이벤트 | 제시된 상품 ID/종류/가격·잔액·구매 가능 여부/불가능 사유 | 상점을 열거나 실제 진열이 바뀔 때 |
| 이벤트 | 구매 시각·상품 ID/종류/가격·성공/실패 사유·전후 잔액·실제 획득량/적용 효과 | 상품 구매를 시도했을 때 |
| 이벤트 → 요약 | 무기별 장착 시간·발사/명중/처치 수·발사체/적중 발사체 수·적 종류별 받은 실제 피해량/피격 횟수 | 발생 시 누적하고 웨이브 완료·중단 시 합계 기록 |
| 이벤트 | 사망 시각·위치·무기/탄약·반경 내 생존 적 수·집계 반경·마지막 피해 출처/실제 피해량 | 플레이어가 사망했을 때, 적·무기를 정리하기 전 상태 기록 |
| 이벤트 | 실제 발사 시각·무기 ID·좌/우 손·실제 발사 위치 | 실제 발사가 성공했을 때 |

## 목적과 공통 기준

한 판의 진행과 플레이어 행동을 기록하여 웨이브 난이도, 무기·탄약 경제, 상점 선택, 슬롯과 전투의 관계, 이동 경로를 분석한다. 이 문서는 구현 기획이다.

- 한 판마다 고유한 `sessionId`를 발급한다. 다시 시작하면 새 ID를 발급한다.
- 모든 기록에 이벤트 종류, 세션 ID, 발생 순서, 게임 시작 후 경과 시간, 웨이브 번호를 넣는다. 웨이브가 아직 없으면 null로 기록한다.
- 실제 시작·종료 시각은 UTC로 기록하고, 경과 시간과 구분한다. 위치는 Unity 월드 좌표(미터)다. FixedUpdate의 플레이어 위치 기록은 `x`, `z`를 각각 남기고, 발사 위치·사망 위치·공격 위치 등 이벤트의 3차원 위치는 `x`, `y`, `z`를 남긴다. 시점은 카메라 로테이션이다.
- 알 수 없는 값은 0으로 대체하지 않고 null 또는 `unknown`으로 표시한다.
- 실시간 기반 로그는 조작 가능한 **매 `FixedUpdate`에 한 번씩** 현재 값을 수집한다. 별도 샘플 간격·주기 타이머·로그 전용 시간 배율을 두지 않고 Unity의 `Time.fixedDeltaTime`을 사용한다.
- 게임 시작 후 경과 시간은 세션이 활성화된 동안 각 FixedUpdate에서 `Time.fixedDeltaTime`을 한 번씩 더한 값이다. 상점에서도 세션 경과 시간은 이어지지만, 조작 불가 상태의 플레이어 위치·적 수 레코드는 생성하지 않는다. 이벤트 로그는 발생 즉시 같은 경과 시간을 읽고, 한 틱 안의 순서는 발생 순서 필드로 구분한다.
- 게임 시간 정지로 FixedUpdate가 실행되지 않으면 해당 기록과 경과 시간 누적도 멈춘다. 재개 후에는 실제 실행되는 틱만 기록하며 중단 구간의 위치를 추정해 채우지 않는다. 적용 중인 fixedDeltaTime이 바뀌면 현재 값을 사용하고 변경 시각·값도 남긴다. 로그를 위해 Unity의 고정 시간 설정을 변경하지 않는다.
- 매 FixedUpdate의 **기록 생성**과 디스크의 **flush**는 구분한다. 쓰기는 버퍼링할 수 있지만 별도 저장 주기 때문에 중간 틱의 기록을 생략하거나 합치지 않는다.

## 상세 기록 항목과 선정 이유

### 게임 시작·종료

- **시작**: 세션 ID, 시작 시각, 빌드·데이터 버전, 맵 ID, Unity에 실제 적용된 `Time.fixedDeltaTime` 값.
- **종료**: 세션 ID, 종료 시각, 총 플레이 시간, 종료 사유, 최종 도달 웨이브, 마지막 완료 웨이브, 총 처치 수. 종료 사유는 사망, 플레이어의 종료·재시작, 기타 확인 가능한 종료로 구분한다.
- 최종 도달 웨이브와 마지막 완료 웨이브는 다를 수 있다. 비정상 종료 등으로 종료 기록을 남기지 못한 세션은 **종료 미확인**으로 분석한다.
- **이유**: 한 판을 식별하고 플레이 시간과 진행 결과를 비교한다.

### 웨이브 시작·종료

- **시작**: 웨이브 번호, 시작 시각, 제한 시간, 예정된 적 종류·수, 체력·소지금·탄종별 예비탄, 장착 무기와 장전탄.
- **종료**: 웨이브 번호, 경과 시간, 종료 사유, 처치 수, 체력·소지금·탄종별 예비탄, 장착 무기와 장전탄, 실제 웨이브 보상·회복량. 적 전멸 시각 또는 전멸까지 걸린 시간은 전멸한 경우에 기록한다.
- 도중에 사망한 웨이브는 **중단**으로 구분하고 그 시점까지의 탄약·전투 요약을 출력한다. 완료 보상이 지급된 것으로 기록하지 않는다.
- **이유**: 웨이브별 난이도와 자원 변화를 확인한다.

### 슬롯 회전 시작·결과 심볼·실제 지급량

- **시작**: 회전 ID, 시각, 비용, 회전 전 소지금, 플레이어 체력, 당시 생존 적 수, 플레이어 위치.
- **결과 확정**: 동일한 회전 ID, 시각, 결과 심볼·당첨 항목, 실제 지급 금액, 실제 지급한 탄종과 탄약량, 지급 후 소지금. 보상이 없으면 보상 0으로 기록한다.
- 종료 등으로 결과가 확정되지 않은 회전은 미완료로 구분한다. 탄약 보상은 장전탄과 예비탄 중 실제 증가한 쪽을 구분한다.
- **이유**: 슬롯의 비용 대비 보상과 전투 중 사용 패턴을 확인한다.

### 탄약 수급·소모 요약

- 탄종별 웨이브 시작·종료 예비탄 및 장전탄, 발사 소모량, 드롭·상점·슬롯 등 출처별 실제 획득량, 탄약 부족 횟수를 기록한다. 장전탄에 직접 지급된 슬롯 보상도 별도 집계한다.
- 재장전은 예비탄에서 장전탄으로의 이동이므로 전체 탄약의 소비나 획득으로 중복 집계하지 않는다. 무기 교체 시 바닥에 남긴 장전탄과 새 무기의 장전탄은 이동과 신규 획득으로 구분한다.
- 부족 횟수는 예비탄이 없어 재장전을 시작하지 못한 횟수와 빈 탄창으로 발사를 시도한 횟수로 구분한다. 연속 입력 집계 단위는 구현 시 명시한다.
- **이유**: 탄종별 고갈과 수급 경로의 효과를 파악한다.

### 상점 상품 제시·구매 시도 결과

- **상품 제시**: 상점을 열거나 진열이 바뀔 때 상품 ID·종류·가격, 당시 잔액, 구매 가능 여부와 불가능 사유를 기록한다.
- **구매 시도**: 상품 ID·종류·가격, 시각, 성공·실패와 실패 사유, 구매 전후 잔액, 실제 획득 수량 또는 적용된 업그레이드.
- **이유**: 제시 대비 구매율과 자금 부족 등 구매하지 못한 이유를 구분한다. 구매 시도 없이 지나간 이유는 단정하지 않는다.

### 무기별 전투 수치 요약·개별 발사 기록

- **개별 사격**: 실제 발사가 성공한 시각, 무기 ID, 좌·우 손과 발사 위치. 입력 시도만으로 기록하지 않는다.
- **무기별 웨이브 요약**: 장착 시간, 발사 횟수, 적 명중 횟수, 처치 수. 교체 시 이전 장착 시간을 누적하고 웨이브 종료·사망 시 현재 구간을 마감한다.
- **받은 피해 요약**: 공격한 적 종류별 플레이어의 실제 체력 감소량과 피격 횟수. 출처를 알 수 없으면 `unknown`으로 기록한다.
- 발사 1회는 하나의 사격 묶음으로 센다. 산탄처럼 발사체가 여러 개일 때 발사체 수와 적중 발사체 수를 별도로 기록한다. 사격 명중 횟수는 한 묶음이 적 하나 이상에 명중한 횟수로 집계한다.
- **이유**: 무기 사용 경향과 적의 위협도, 사격과 슬롯 행동의 시간적 관계를 확인한다.

### 플레이어 사망 시 상태·마지막 피해 기록

- 시각·웨이브, 위치, 장착 무기 ID, 탄종·장전탄·예비탄, 주변 생존 적 수와 집계 반경, 마지막 피해의 적 종류·적 무기·실제 피해량·공격 위치. 확인할 수 없는 출처는 `unknown`으로 기록한다.
- 주변 적 반경은 **우선 10m를 제안**하며 실제 적용한 반경을 함께 남긴다. 사망 전 피해는 전투 요약의 적 종류별 누적 피해와 함께 해석한다.
- **이유**: 어떤 무기·위치·적 구성에서 사망했는지 살펴본다.

### FixedUpdate별 현재 위치·생존 적 수 기록

- 다음 두 레코드는 조작 가능한 각 FixedUpdate에서 같은 경과 시간을 사용해 생성한다. 경과 시간은 `Time.fixedDeltaTime` 기준이며, 별도 간격을 기다렸다가 일부 틱만 수집하지 않는다.
- 전투가 끝나고 상점으로 진행되기 전에도 기록한다. 직접 조작 가능한 상태라면 이동 입력이 없어 위치가 그대로여도 매 틱 기록한다. 상점·사망 등 조작 불가 상태에서는 이 두 레코드를 생성하지 않는다.

#### 현재 시각·플레이어 위치(x, z)

- 각 FixedUpdate에 현재 경과 시간 `elapsedSeconds`, 플레이어 월드 위치 `x`, `z`, 카메라 `yaw`, `pitch`, 웨이브 번호, 장착 무기, 게임 단계를 기록한다.
- 하나의 기록은 그 틱의 현재 값이다. 여러 시각의 `x`, `z`를 순서대로 연결하면 이동 경로를 분석할 수 있다.
- **이유**: 주로 사용하는 지형·이동 경로를 확인한다.

#### 현재 시각·적 종류별 생존 수

- 플레이어 위치를 기록하는 같은 FixedUpdate에 현재 `elapsedSeconds`, 웨이브 번호와 `적 종류 ID → 생존 수`를 기록한다.
- 해당 웨이브에 등장하는 적 종류만 포함한다. 예정된 종류가 아직 스폰되지 않았거나 이미 전멸했다면 0으로 기록하며, 해당 웨이브에 등장하지 않는 종류는 제외한다.
- **이유**: 현재 상황을 유추한다.

## 분석과 구현 시 유의점

- 무기 사용률과 장착 중 사망은 밸런스의 단서다. 장착 시간·웨이브·상황을 함께 비교한다. 슬롯 결과와 행동의 시간적 관계도 원인이라고 단정하지 않는다.
- 상점 구매율은 제시 횟수와 구매 가능 상황을 함께 살핀다.
- 현재 `GameManager`의 `WaveStarted`·`WaveEnded`·`GameOver`, `WaveController`의 `EnemyKilled`, `SlotMachinePresenter`의 `SpinStarted`·`SpinResolved`, `PlayerWeapon`의 `Fired`·`EnemyImpact`가 연결 후보다. 이벤트에 필요한 정보가 없으면 발생 지점에서 확장한다.
- `PlayerHealth`의 기존 피해 이벤트만으로 적 종류·무기·피해량 전체를 식별할 수 없다. 적 공격과 발사체 피해 경로에서 출처 정보를 전달해야 한다. `AmmoInventory.Changed`도 변화 원인을 담지 않으므로 드롭·구매·재장전 등 발생 지점에서 원인을 구분한다.
- 세션·웨이브 요약의 중복 출력을 막고 사망 중단도 누락하지 않는다. 기존 게임 보상 처리 순서는 유지한다.
- 검증: 새 게임·재시작의 세션 ID, 사망 중단, 슬롯 시작·결과 연결, 재장전 중복 집계 방지, 구매 실패, 산탄 명중 집계, 조작 가능한 FixedUpdate 횟수와 위치/적 수 기록 개수의 일치, fixedDeltaTime에 따른 경과 시간, 정지·재개와 저장 위치를 확인한다.
