# 로그 시스템 6차: 슬롯 시작·결과·미완료

구현일: 2026-10-31. Unity 실행·Play Mode·Unity 빌드·Unity API 실행 검증은 하지 않았다.

## 소유자와 회전 수명

GameManager가 세션별 LogSlotCollector를 소유한다.
SlotMachinePresenter는 기존 CanInteract와 결제를 수행한 뒤, 실제 reels.BeginSpin이 true인 경우에만 Start를 호출한다.
false이면 기존대로 환불하며 성공 회전·spinId는 만들지 않는다.
중복 요청의 slot_spin_rejected는 유지하되 회전 ID를 새로 발급하지 않는다.

LogSlotCollector는 기계 객체의 참조별로 진행 회전 한 개를 유지한다.
동일 기계가 다시 Start를 호출해도 기존 회전 중에는 새 ID를 만들지 않는다.
각 LogSpinContext는 원래 세션/수집기·spinId·시작 웨이브/phase/시각·복사한 세 릴과 심볼 ID를 소유한다.
결과나 incomplete가 확정되면 소유 기계와 임시 탄약 참조를 해제한다.

실제 릴 콜백에는 별도 회전 토큰이 있다.
현재 토큰과 동일할 때만 지급 함수에 진입하고, 진입 전에 토큰을 폐기한다.
동일 콜백 반복과 이전 회전의 늦은 콜백이 다음 회전의 spinning=true를 이용해 다시 지급하는 경우를 막는다.
로그 비활성/저장 실패에서도 이 중복 지급 방지는 동작한다.

기존 SpinStarted(int), SpinHealed(float), SpinResolved(SlotOutcome,int,string) 구독자와 회복·결제·보상 정책은 유지한다.
새로운 입력 차단·카메라 고정·UI·씬/프리팹 저작을 추가하지 않는다.

## 공통 봉투와 실제 3릴

기존 LogSession의 sessionId/sequence/elapsedSeconds/waveNumber/phase를 사용한다.
추가 시계·난수·재추첨은 없다. RollFaces에서 뽑힌 배열을 그대로 복사한다.
각 face는 현재 SlotMachineData.symbols의 reelIndex로 id를 조회하므로 테이블 배열 위치로 오해하지 않는다.
해당 심볼 ID를 알 수 없다면 null이다.

시작과 결과의 faces/symbolIds는 같은 순서의 3개 값이다.
pairFace/tripleFace에서 원본 릴을 역산하지 않는다. 외부 배열을 나중에 바꿔도 기록은 바뀌지 않는다.

## 이벤트

### slot_spin_started

spinId, originWaveNumber, originPhase, startedElapsedSeconds,
actualCost(할인 적용 후 실제 결제 비용), baseCost(지급 기준 기본 베팅),
spinSeconds(기존 퍽 적용 회전 시간 입력값), faces, symbolIds, before.

before는 결제 전 LogSlotState다:
waveNumber/phase/elapsedSeconds, player의 소지금·체력·위치·손/개체/탄종별 장전탄·공유 예비탄/최대량, enemies의 생존 수/종류별 수.
비용은 TrySpend가 성공한 인자이며, 환불된 요청은 여기에 포함하지 않는다.
실제 릴 연출의 최소 시간 clamp 등 기존 View 정책은 바꾸지 않는다.

### slot_spin_healed

spinId, actualHealthRestored, healthAfter.
성공 회전 시작을 먼저 보장하고 기존 RecoverForSlotSpin 적용 후 실제 회복량을 같은 ID로 한 번 기록한다.
시작 시 체력은 회복 전이고, 이 이벤트는 최대 체력에서 잘린 실제 회복량이다.
기존 SpinHealed/SpinStarted 이벤트 호출 의미는 유지한다.

### slot_spin_resolved

spinId, originWaveNumber/phase, startedElapsedSeconds, resolvedElapsedSeconds,
원본 faces/symbolIds, outcome, piggyMultiplier, cashBonusMultiplier,
calculatedPayout, plannedPartIds, actualMoneyDelta, balanceAfter,
ammoGranted, before, after.

- 봉투의 phase/waveNumber는 결과가 실제 발생한 단계/웨이브다.
- outcome은 실제 SlotOutcome의 triple/pair/multiplier/탄약·파츠·꽝·nearMiss 값 복사다.
- cashBonusMultiplier는 기존 kill bonus·퍽·저금통을 합친 현금 계산 배율이다. 현금 배수 계산을 하지 않은 결과는 null이다.
- calculatedPayout은 기존 배수 현금 계산 결과다. actualMoneyDelta는 지급 직전/직후 잔액의 실제 차이이며 현물 대체 현금까지 포함한다.
- 지급 전후 상태를 모르면 실제 차이는 null이다. 정상 꽝/최대 상태에서 확인된 0은 0이다.
- plannedPartIds는 계획 ID로 명시하며 실제 장착/획득 개수라고 주장하지 않는다.
- before/after는 결과 지급을 직접 둘러싼 현재 상태다. 회전 중 무기 교환·아킴보 전환이 있으면 지급 시점의 실제 무기/손을 보여준다.

actualMoneyDelta는 지급 구간의 순 잔액 변화다. 해당 구간의 외부 재진입 코드가 추가 거래를 수행하면 그 순 변화도 포함된다.
현재 Update 프레임 사이의 사격·이동 등은 지급 전 스냅샷에 반영되어 회전 전체의 자원 변화를 보상으로 오인하지 않는다.

### slot_spin_incomplete

spinId, originWaveNumber/phase, startedElapsedSeconds, status=incomplete, reason.
결과·실제 보상량을 추측하지 않으며 가짜 0 보상을 출력하지 않는다.
게임 종료 사유 또는 payout_interrupted/result_collection_failed를 사용한다.
지급 중 예외가 발생하면 부분 탄약 변경은 원래 ammo_changed에 남을 수 있지만 완전한 결과라고 만들지 않는다.

## 5차 탄약 연결

SlotRewardInfo.Apply에 causeId=spinId를 전달한다.
실제 Add/직접 장전 보충은 기존 LogAmmoCollector 한 경로만 집계한다.
LogAmmoCollector.Observed를 세션 소유자가 구독해 해당 spinId의 변경을 값 복사한다.

ammoGranted는 원래 ammo_changed payload의 transactionId/causeId/source/탄종/개체/손/실제 reserveDelta/loadedDelta/acquired 등을 참조용으로 보존한다.
부분 지급·상한으로 잘린 양·실제 0을 그대로 사용한다. 계획 ammoAmount나 이론상 탄창 크기로 채우지 않는다.
결과 출력은 AmmoInventory.Add/GrantSlotAmmo나 경제 합계를 다시 호출하지 않는다.
분석 시 ammoGranted와 원본 ammo_changed를 서로 다른 획득으로 더하면 안 된다. 경제 총량은 5차 요약/원본 사건을 사용한다.

현재 슬롯은 예비탄 현물 보상을 사용한다. 직접 장전 API도 기존 GrantSlotAmmoForCause(spinId)로 연결 가능하지만 보상 정책을 변경하지 않았다.
탄약 결과 구독은 GameManager 정리 시 해당 소유자만 해제한다. 실패한 관측자는 게임 지급이나 다른 관측자를 막지 않는다.

## 경계·종료·실패

상점에서 끝난 회전은 원래 시작 웨이브를 유지하고 봉투는 shop이다.
다음 웨이브까지 넘어갔다면 originWaveNumber와 현재 waveNumber가 다를 수 있다.
탄약은 5차의 발생 시점 정책을 따른다. 닫힌 이전 웨이브 합계를 수정하지 않고 다음 시작 상태에 반영한다.

LogGameLifecycle.RegisterSessionEndObserver가 세션 종료 직전 pending을 마감한다.
사망 순서는 death_snapshot → 중단 wave_summary → slot_spin_incomplete → session_end다.
나가기/종료도 해당 요약과 incomplete를 session_end보다 먼저 기록한다.
각 종료 관측자 실패를 개별 격리하고 참조를 해제한다. 같은 종료 호출을 반복해도 중복 마감하지 않는다.

이미 끝난 세션의 LogSpinContext는 새 세션의 수집기가 받지 않는다.
세션 종료 뒤 도착한 릴 콜백은 기존 게임 보상 정책대로 동작할 수 있지만 종료한 분석 세션을 재개하거나 새 세션에 결과를 기록하지 않는다.
따라서 incomplete는 분석 세션이 끝날 때 미확정이라는 뜻이다.

시작 스냅샷/직렬화 관측 실패는 진단에 남기고 게임 회전을 막지 않는다.
결과 직렬화가 실패하면 가능한 경우 incomplete로 마감한다.
로그 비활성·디스크 실패에서는 기존 공통 정책대로 기록을 보장하지 않으며 결제/보상은 계속 진행한다.
강제 프로세스 종료로 session_end가 없으면 시작만 남은 회전은 종료 미확인 상태로 해석한다.

## 검증과 사용자 Unity 확인

제어 가능한 합성 입력·실제 AmmoInventory/PlayerWallet을 사용한 검사는 `.omo/verification/log-phase6/`에 있다.
`Docs/로그-시스템-6차.synthetic.jsonl`은 주입 입력의 합성 예시이며 Unity 플레이 로그가 아니다.
기존 구형 start/result 작성 API를 제거하고 통합 검사도 새 회전 계약으로 전환했다.

사용자 Unity 확인:

1. 실제 3릴 순서/심볼 ID와 start/result의 동일 spinId, 결제 전 잔액·체력·위치·생존 수를 비교한다.
2. 정상/꽝/현물 탄약/현금 포함 결과, 할인 비용·퍽·저금통 배율, 실제 지급 후 잔액을 확인한다.
3. 릴 연결 불량 등 BeginSpin 실패 시 환불되고 성공 시작이 없는지 확인한다. 연속 입력/콜백 반복 시 보상이 한 번인지 확인한다.
4. 회전 중 이동·시점·사격·무기 교환·아킴보를 사용하고 기존 HUD·소리·조작이 동일한지 확인한다.
5. 예비탄 상한/부분 보충과 직접 장전 API의 양손/가득 참/사망 가드를 비교하고 ammoGranted와 원본 transactionId가 일치하는지 확인한다.
6. 웨이브→상점 결과, 사망·타이틀 복귀·앱 종료·씬 파괴 시 incomplete와 session_end 순서, 재시작 후 ID 분리를 확인한다.
7. Play Mode 종료 후 `Tools > POC > Verify Unified Telemetry File`로 최신 파일의 회전 1:1·심볼 동일성·탄약 원본 참조를 검사한다. 이 메뉴 자체는 이번 작업에서 실행하지 않았다.
