# POC2 작업 지침 (Work Guidelines)

> 작업 세션 필독. 기획 상세는 `POC-기획노트.md` 참조, 마지막 업데이트: 2026-10-29

## 1. 씬 구성
- 씬 배치 순서: **Preload → Title → Game** (빌드 씬 인덱스 이 순서 유지)
- Preload: 테이블/에셋 로드, Title: 진입/시작, Game: 본플레이

## 2. 데이터
- **확정된 수치는 전부 테이블화** — **스크립터블 오브젝트(SO) 대신 파일 테이블(JSON) 우선**
  - 표준 방식: `Assets/Resources/*.json` + 직렬화 자료 클래스 + **TableManager(원 프로젝트 구조)로 로드/검증** (결정 #22)
  - SO 사용은 불가피한 경우(장기 참조·인스펙터 연결이 필수)에만 예외
  - 대상: 페이 테이블·weight(§1-3), spinCost, 웨이브 시간/적 구성/스칼링, 상점 가격, 무기 스탯(사거리·연사력·탄창), 슬롯 회전 시간
- 코드 상수 하드코딩 금지. 예외는 예외 주석과 함께

## 3. 아키텍처
- UI는 **MVP 패턴** (Model–View–Presenter)로 구조화. View는 스크립트에서 코드 생성하지 말고 프리팹에 배치
- **프로시저럴 코드 생성 지양** — 메시/오브젝트/레벨 구성은 프리팹·씬 에디터 기반 제작. 런타임 new/instantiate는 게임플레이 스폰(적·탄환·파티클)만 허용

## 4. 코딩 스타일
참고: https://namu.wiki/w/코딩 스타일

### 대원칙
- 코드 정리는 **Visual Studio 기준 Ctrl+K, R** 정렬 적용된 상태로 커밋
- 커밋 전 코드 정리(Ctrl+K, R) 필수 실행
- 코드 블록은 **BSD(Allman) 방식** — 여는 중괄호는 새 줄
  ```csharp
  void GetData()
  {
      if (isReady)
      {
          StartGame();
      }
  }
  ```
- 1줄짜리 코드 블록(한 줄 if/for 등) 지양 — 중괄호 생략하지 않고 본문은 새 줄

### 네이밍
| 항목 | 규칙 | 예시 |
|------|------|------|
| 표기 | **CamelCase**(변수/필드) 권장. 너무 길거나 가독성 떨어지면 snake_case 허용 | `canvasPanel` / `canvas_panel` |
| 함수명 | 대문자 시작 | `void GetData()` |
| 변수명 | 소문자 시작 | `int count = 0;` |
| 클래스 | 대문자 시작 PascalCase | `class TableData {}` |
| 파라미터 | **`_` 접두사 필수** | `void SetDamage(int _damage)` |
| const / static | **전부 대문자 + 언더스코어** | `const int MAX_LENGTH = 100;` `static int MAX_WIDTH = 100;` |

- 멤버변수는 일반 camelCase로 작성 (타입/스코프 접두사 같은 헝가리안 표기법 금지)

## 5. 커밋
- 커밋 전: ① 코드 정리(Ctrl+K, R) ② 컴파일 경고 확인
- 커밋 메시지는 "[범위] 내용" 형식 권장 (예: `[slot] 페이테이블 JSON 연동`)
